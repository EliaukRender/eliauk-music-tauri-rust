# 架构设计

## 技术栈

| 层       | 选型                                                     | 说明                                                  |
| -------- | -------------------------------------------------------- | ----------------------------------------------------- |
| 桌面容器 | Tauri 2（Rust）                                          | 系统 WebView：Windows 为 WebView2，macOS 为 WKWebView |
| 前端框架 | Vue 3（`<script setup>` + TS）、Vite 8                   |                                                       |
| 状态管理 | Pinia 4 + pinia-plugin-persistedstate                    | 偏好类状态持久化到 localStorage                       |
| 路由     | vue-router 5（hash 模式）                                | Tauri 自定义协议加载资源，hash 模式无需回退           |
| UI       | naive-ui + Tailwind CSS v4                               | 组件交给 naive-ui，布局与样式交给 Tailwind            |
| 图标     | Iconify（unplugin-icons，图标集 `ri` Remix Icon）        | 构建期内联 SVG，离线可用                              |
| 工具     | @vueuse/core、axios                                      |                                                       |
| 音乐 API | @neteasecloudmusicapienhanced/api                        | NeteaseCloudMusicApi 社区续作，支持内嵌与远程两种形态 |
| 工程     | pnpm workspace、ESLint 10 + Prettier、husky + commitlint |                                                       |

## 进程模型

```
┌──────────────────────── Tauri 应用 ────────────────────────┐
│                                                            │
│  WebView（Vue）            Rust 主进程                     │
│  ┌──────────────┐  invoke  ┌───────────────────────────┐   │
│  │ api/http.ts  │ ───────▶ │ get_api_endpoint          │   │
│  │ (axios)      │ ◀─────── │ api_server（sidecar 管理）│   │
│  └──────┬───────┘  event   │ tray / window / plugins   │   │
│         │                  └────────────┬──────────────┘   │
│         │ HTTP                          │ spawn / kill     │
│         ▼                               ▼                  │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ ncm-api sidecar（Node 运行时 + NCM API，127.0.0.1）  │  │ ← 仅内嵌形态
│  └──────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────┘
          远程形态：WebView 直接请求 VITE_API_BASE_URL
```

- 前端只和 **HTTP API** 以及少量 **Tauri 命令/事件** 打交道，不直接感知 sidecar。
- 音乐数据请求由 WebView 直连 API 服务，不经 Rust 中转，调试链路更短；sidecar 的 CORS 会回显 `tauri://localhost` / `http://tauri.localhost`。
- Rust 端职责：窗口与系统集成（托盘、单实例、窗口状态、日志），内嵌形态下管理 sidecar 生命周期。

API 双形态的细节见 [API服务接入.md](./API服务接入.md)。

```
eliauk-music-tauri-rust/

├── docs/                    # 项目文档（功能方案/ 为各功能迁移方案）
├── scripts/                 # 工程脚本
├── sidecar/ncm-api/         # NCM API sidecar 子包（pnpm workspace）
│   ├── src/index.cjs        # sidecar 入口：端口、就绪信号、父进程看护
│   └── scripts/build.mjs    # pkg 打包为 ncm-api-<target-triple>
├── src/                     # Vue 前端（只放业务代码，测试在 tests/）
│   ├── api/                 # http.ts（axios 实例）+ modules/（按业务拆分）+ adapters/（字段归一化）
│   ├── assets/styles/       # 全局样式与 Tailwind 主题 token
│   ├── components/<领域>/   # 跨页面复用的组件：layout、player、song、playlist、artist、user、spectrum、common
│   ├── composables/         # useXxx 组合式函数；app/ 为只在主窗口挂载的应用级同步与桥接
│   ├── constants/           # 路由名、事件名、菜单、播放模式等常量（as const 对象）
│   ├── features/            # 跨组件的功能模块，如 context-menus/
│   ├── layouts/             # 页面骨架布局
│   ├── router/
│   ├── services/            # 与界面无关的服务：player/（音频引擎）、spectrum/、context-menu/、tauri/（Tauri 桥接）
│   ├── stores/              # Pinia（setup store）；较大的 store 为目录模块，如 player/
│   ├── theme/               # 品牌色、naive-ui 主题覆盖
│   ├── types/               # 仅类型声明
│   ├── utils/               # 纯函数工具，如 lyric/ 解析
│   ├── views/<页面>/        # 页面，页面私有组件放在其 components/ 下
│   ├── App.vue / MiniApp.vue # 主窗口 / mini 窗口的根组件，由 main.ts 按窗口 label 选择
│   └── main.ts
├── tests/unit/              # 前端单元测试，目录结构与 src/ 一一对应
└── src-tauri/
    ├── src/
    │   ├── lib.rs           # 插件注册、生命周期、窗口事件
    │   ├── api_server/      # API 形态与 sidecar 管理（embedded.rs 受 feature 控制）
    │   ├── window/          # 主窗口与关闭行为（mod.rs）、mini 窗口（mini.rs）、macOS 原生调用（macos.rs）
    │   ├── system/          # 托盘、系统媒体中心、全局快捷键、播放状态同步
    │   ├── credential.rs    # 登录凭据（系统钥匙串 / 凭据管理器）
    │   ├── events.rs        # 与前端共享的事件名与指令
    │   └── **/tests.rs      # 各模块的单元测试，与业务代码分文件
    ├── capabilities/        # 前端可调用的权限白名单
    ├── icons/               # 生成的应用/托盘图标
    ├── binaries/            # sidecar 产物（不入库）
    ├── tauri.conf.json              # 基础配置
    ├── tauri.macos.conf.json        # macOS 覆盖（Tauri 自动合并）
    ├── tauri.windows.conf.json      # Windows 覆盖（Tauri 自动合并）
    └── tauri.embedded.conf.json     # 内嵌形态覆盖（通过 --config 显式合并）
```

## 分层约定

- **views** 只做页面编排：调用 `api/modules` 获取数据、读写 store，不直接使用 axios 或 Tauri API。
- **services/tauri** 是唯一允许 import `@tauri-apps/*` 的业务层（`utils/platform.ts` 例外），方便在浏览器调试时降级，也便于替换实现。
- **api/modules** 负责接口调用和返回值裁剪；多个接口字段不一致时，在 `api/adapters` 归一化为 `types/music.ts` 中的类型（见 [功能方案/00-索引与里程碑.md](./功能方案/00-索引与里程碑.md)）。
- **stores** 使用 setup store；只有偏好类字段持久化，通过 `persist.pick` 显式列出。

## 配置合并顺序

Tauri CLI 按以下顺序做 JSON Merge Patch，后者覆盖前者（数组整体替换，所以平台文件里的 `app.windows` 需要写完整）：

1. `tauri.conf.json`
2. `tauri.<platform>.conf.json`（按当前构建平台自动选择）
3. `--config` 传入的文件（`tauri.embedded.conf.json`）

## 主题

- 品牌色的唯一来源是 `src/theme/tokens.ts`，由它生成 naive-ui 的 `themeOverrides`；`main.css` 中的 `--app-primary*` 必须与之保持一致。
- 语义色（`bg`、`surface`、`elevated`、`fg`、`muted`、`line`、`primary`）通过 CSS 变量和 Tailwind `@theme inline` 暴露为工具类，深色模式只切换变量。
- `index.html` 中的 `<meta name="naive-ui-style">` 保证 naive-ui 样式先于 Tailwind 注入，这样 Tailwind 工具类可以覆盖组件样式。
