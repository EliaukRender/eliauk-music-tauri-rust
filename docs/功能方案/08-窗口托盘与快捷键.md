# 08 窗口控制 / 托盘 / 快捷键

## 1. 背景

### 旧实现位置

| 文件                                                                                         | 内容                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/main/ipcMain/mainWin/winUihandler.ts`                                                   | 全屏切换、最大化切换、最小化、关闭；拖拽设位置（带屏幕边界判断，多显示器有 todo）；监听 enter/leave-full-screen、maximize、minimize、restore 事件并回传给渲染进程；退出全屏时恢复原来的 bounds |
| `src/main/ipcMain/appData/mainWinData.ts`                                                    | 主进程内存中的窗口状态                                                                                                                                                                         |

| `src/renderer/hooks/useUpdateWindowPosition.ts`、`useDoubleClick.ts`                         | 自己实现的拖拽和双击最大化                                                                                                                                                                     |
| `src/main/main.ts#setTray`                                                                   | 托盘：「打开」「退出」；单击时切换最小化和 `skipTaskbar`                                                                                                                                       |

### 已知缺陷

- 拖拽依赖自定义 IPC 和手工计算坐标，多显示器和缩放屏幕的情况没有处理。
- 在 macOS 的 activate 事件中重建窗口后，IPC handler 仍然绑在旧的窗口引用上。
- 渲染进程的监听没有 unlisten。
- 托盘单击在 macOS 上的行为不符合平台习惯（mac 上托盘点击应该弹出菜单）。
- 在输入框中按 Space 或 Enter 也会触发播放或最大化，因为全局拦截，没有判断焦点。
- 没有全局快捷键，也没有媒体键支持。

骨架已完成的部分：mac 使用 Overlay 标题栏和原生红绿灯；win 使用无边框窗口和 `WindowControls.vue`（最小化、最大化、关闭）；`data-tauri-drag-region` 拖拽；基础托盘（显示、退出）；single-instance（二次启动时聚焦已有窗口）；window-state（记住主窗口尺寸和位置）。

## 2. 目标与范围

本期实现：

- **窗口**：双击标题栏最大化或还原；全屏切换（歌词页按钮和快捷键）；最大化、全屏状态同步到 UI；关闭按钮的行为可配置（最小化到托盘或直接退出）
- **托盘**：菜单改为「当前歌曲（禁用项，仅展示）/ 播放·暂停 / 上一首 / 下一首 / mini 播放器 / 显示主窗口 / 退出」，菜单项随播放状态更新；mac 使用 template 单色图标
- **应用内快捷键**：Space 播放/暂停；Ctrl 或 Cmd + ←/→ 切歌；←/→ 快退、快进 5 秒；Ctrl 或 Cmd + ↑/↓ 调音量；Esc 退出全屏或关闭歌词；Cmd/Ctrl + Enter 最大化；F12 仅在开发环境打开开发者工具
- **全局快捷键**（默认关闭，可在设置中开启并自定义）：播放/暂停、上一首、下一首、显示或隐藏 mini
- **媒体键和系统媒体中心**：Windows SMTC、macOS 控制中心「正在播放」

本期不做：

- 快捷键冲突检测 UI（只做注册失败时的提示）

## 3. 方案设计

### 3.1 窗口控制

- `src/services/tauri/window.ts`（骨架已有）补充 `toggleFullscreen()`、`onWindowStateChange(cb)`（监听 `onResized`，通过 `isMaximized` 和 `isFullscreen` 判断状态）。
- `stores/app.ts` 新增 `isMaximized`、`isFullscreen`，由上面的监听写入。
- **双击标题栏**：
  - win：在 `TitleBar.vue` 上 `@dblclick` 调用 `toggleMaximize()`。
  - mac：Overlay 标题栏区域的双击由系统处理（遵循「系统设置 > 桌面与程序坞 > 连按标题栏」的设置），前端**不要**再绑定，否则会触发两次。
- **关闭行为**（已实现）：`stores/settings.ts` 中的 `closeBehavior: 'minimize' | 'exit'`，默认 `'minimize'`（隐藏到托盘，mac 同时驻留 Dock），可在设置页切换为退出应用。前端通过 `useWindowSettingsSync` 在启动时和变更时调用 `set_close_behavior` 同步给 Rust，由 `CloseRequested` 统一执行，两个平台逻辑一致。
  - Rust 在 `on_window_event` 中拦截 `CloseRequested`：如果是 tray，就 `prevent_close()` 然后 `hide()`。
  - mac 上 Cmd+Q 和 Dock 的「退出」走 `RunEvent::ExitRequested`，不受这个设置影响。
  - mac 在 `RunEvent::Reopen`（点击 Dock 图标）时要 show 主窗口。
- **退出全屏后恢复尺寸**：Tauri 和系统会自动恢复，不需要像旧项目那样手动 setBounds。

所需 capability（`default.json`）：`core:window:allow-minimize`、`allow-toggle-maximize`、`allow-close`、`allow-set-fullscreen`、`allow-is-fullscreen`、`allow-is-maximized`、`allow-start-dragging`、`allow-hide`、`allow-show`。

### 3.2 托盘增强：`src-tauri/src/tray.rs`

- 菜单项用 `MenuItem` 创建并保存句柄。收到前端的 `tray://update` 事件（payload 为 `{ title, artist, isPlaying }`）时，调用 `set_text` 更新「当前歌曲」和「播放/暂停」两项的文案。
- 菜单点击统一转成 `emit_to("main", "player://command", {...})`（与 07 共用同一个指令通道），「mini 播放器」调用 `toggle_mini_player`。
- 图标：
  - mac 使用 `icons/tray/tray-template.png`（`@2x` 36px，黑色加透明），并设置 `icon_as_template(true)` 以适配深色和浅色菜单栏；
  - win 使用彩色的 `icons/32x32.png`。
  - 图标素材由骨架的图标设计产出。
- 点击行为：
  - win 左键单击时 show 并聚焦主窗口，右键弹出菜单；
  - mac 左键单击就弹出菜单（`show_menu_on_left_click(true)`），这是平台习惯。
- 托盘提示：`set_tooltip("歌名 - 歌手")`，只在 win 上有效。

### 3.3 快捷键

**应用内**：`src/composables/useHotkeys.ts`，基于 `@vueuse/core` 的 `useMagicKeys` 或 `onKeyStroke`，在 `DefaultLayout.vue` 中挂载。

- 焦点在 `input`、`textarea`、`[contenteditable]` 中时忽略（修复旧缺陷）。
- 修饰键统一抽象为 `Mod`：mac 上是 `metaKey`，win 上是 `ctrlKey`，通过 `platform()` 判断。
- 快捷键表定义在 `src/constants/hotkeys.ts`（const 对象），设置页可以展示。

**全局**：使用 `tauri-plugin-global-shortcut`。

- 在 Rust 端注册，用 settings 中的配置调用 command `set_global_shortcuts(list)`，这样重启后可以自动恢复。
- 注册失败（被其他应用占用）时返回错误列表，由前端提示。
- 默认组合：`CmdOrCtrl+Alt+Space`、`CmdOrCtrl+Alt+Left/Right`、`CmdOrCtrl+Alt+M`。

**媒体键和系统媒体中心**：

- 首选方案：使用 Rust crate `souvlaki`，它跨平台覆盖 Windows SMTC 和 macOS MPRemoteCommandCenter/NowPlaying。
  - 前端通过 `media://update`（标题、歌手、封面 URL、时长、播放状态）推送元数据；
  - 系统媒体按键回调转成 `player://command`。
  - Windows 下 souvlaki 需要 HWND，从主窗口的 `hwnd()` 获取。
- 备选方案：`navigator.mediaSession`。WebView2 对它支持较好，可以对接 SMTC；WKWebView 对 mediaSession 的支持不完整，mac 上不可靠。所以不作为首选。

## 4. Windows / macOS 差异汇总

| 项目           | macOS                                                                   | Windows                                            |
| -------------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| 窗口按钮       | 原生红绿灯（Overlay）                                                   | 自绘 `WindowControls`                              |
| 双击标题栏     | 系统处理                                                                | 前端 `@dblclick`                                   |
| 关闭           | 根据 `closeBehavior` 决定；Cmd+Q 始终退出；hide 后点击 Dock 触发 Reopen | 根据 `closeBehavior` 决定；hide 后可从托盘恢复     |
| 托盘           | 左键弹出菜单，template 单色图标                                         | 左键显示主窗口，右键弹出菜单，彩色图标，有 tooltip |
| 修饰键         | Cmd                                                                     | Ctrl                                               |
| 媒体中心       | MPNowPlayingInfoCenter                                                  | SMTC                                               |
| 全局快捷键权限 | 通常不需要辅助功能权限（热键 API）                                      | 无                                                 |
| 全屏           | 独立 Space，有动画                                                      | 覆盖整个屏幕                                       |

## 6. 验收标准

- win：双击标题栏最大化或还原；关闭按钮在 minimize 模式下隐藏窗口，托盘左键可以恢复。
- mac：Cmd+Q 退出；关闭窗口后点击 Dock 图标能重新显示；托盘图标在深色和浅色菜单栏下都清晰。
- 托盘菜单实时显示当前歌曲，播放/暂停文案正确。
- 在搜索框中输入空格不会触发暂停。
- 开启全局快捷键后，在其他应用中按快捷键能控制播放；如果快捷键被占用，会提示失败。
- 键盘媒体键（win）和控制中心、耳机线控（mac）都能控制播放，并显示封面和歌名。

## 7. 风险与待决策项

- **关闭按钮的默认行为**（已决策）：默认最小化到托盘，设置页可改为退出应用，不做首次询问弹窗。
- souvlaki 在 mac 上需要主线程的 run loop，与 Tauri 的事件循环集成需要验证。如果不稳定，就退回到 win 使用 mediaSession、mac 使用 objc2 直接调用 MPRemoteCommandCenter 的方案。
- 全局快捷键默认是否开启：建议关闭，避免与用户其他软件冲突。
