# 01 二维码登录

## 1. 背景

旧项目的鉴权依赖自建后端：

- `src/renderer/store/modules/userReducer.ts` 只存了一个 `token` 字段，并通过 redux-persist 持久化（`store/persisConfig/index.ts`）。
- `src/renderer/api/index.ts` 在请求头中写入 `token`，收到 401 时清空 token。

已知缺陷：

- 响应拦截器里调用了 `useDispatch()`。这违反 Hooks 规则，一旦触发 401 就会直接抛错。
- 没有登录界面，token 的来源不明确。

迁移到网易云 API 后，用户歌单、喜欢歌曲、每日推荐、高音质等能力都需要网易云的登录态，所以**登录是 M2 所有功能的前置条件**。

## 2. 目标与范围

本期实现：

- 二维码登录：生成二维码、轮询扫码状态、登录成功后拉取账号信息
- 登录态持久化，冷启动时静默校验
- 退出登录
- 用户头像与昵称展示（侧边栏顶部或标题栏）

本期不做：

- 手机号 / 邮箱密码登录。网易云风控严格，容易触发「安全验证」，成功率低。
- 验证码登录、第三方登录
- 多账号切换

## 3. 方案设计

### 3.1 登录态的传递方式

API 服务（无论内嵌还是远程）与 WebView 不同源。WebView 的 origin 是 `tauri://localhost` 或 `http://tauri.localhost`，API 在 `http://127.0.0.1:<port>` 或远程域名，所以浏览器 cookie 不可靠：mac 下 WKWebView 的第三方 cookie 策略很严格。

结论：**不依赖浏览器 cookie，改为显式传递 `cookie` 参数**，与参考项目 AlgerMusicPlayer 的做法一致。

- 登录成功后，`/login/qr/check` 返回 `code=803` 并附带 `cookie` 字符串，前端把它存进 `userStore.cookie`。
- `api/http.ts` 的请求拦截器负责注入：GET 请求放进 `params.cookie`，POST 请求放进 `data.cookie`。
- 调用 `/login/qr/check` 时要带 `noCookie: true`，防止旧 cookie 干扰轮询结果。

### 3.2 文件划分

| 文件                                 | 职责                                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------------------- |
| `src/api/modules/login.ts`           | `getQrKey()`、`createQr(key)`、`checkQr(key)`、`getLoginStatus()`、`getAccount()`、`logout()` |
| `src/stores/user.ts`                 | 登录态与用户信息                                                                              |
| `src/composables/useQrLogin.ts`      | 二维码生命周期：生成、轮询、过期重建、组件卸载时停止轮询                                      |
| `src/components/user/LoginModal.vue` | naive-ui `NModal`，展示二维码和状态文案                                                       |
| `src/components/user/UserEntry.vue`  | 侧边栏顶部的头像入口，未登录时显示「点击登录」                                                |

### 3.3 Store 设计：`stores/user.ts`

```ts
type UserProfile = { userId: number; nickname: string; avatarUrl: string; vipType: number }

state: {
  cookie: string // 持久化
  profile: UserProfile | null // 持久化，用于冷启动时的首屏展示
}
getters: {
  isLoggedIn: boolean // !!cookie && !!profile
  isVip: boolean // profile?.vipType > 0，决定音质上限
}
actions: {
  loginWithCookie(cookie) // 保存 cookie → 调用 getAccount → 写入 profile
  refreshLoginStatus() // 冷启动时调用 /login/status，失效则调用 clear()
  logout() // 调用 /logout（失败也忽略）→ clear()
  clear()
}
persist: {
  pick: ['cookie', 'profile']
}
```

### 3.4 接口

| 接口                   | 关键参数               | 说明                                                              |
| ---------------------- | ---------------------- | ----------------------------------------------------------------- |
| `GET /login/qr/key`    | `timestamp`            | 返回 `data.unikey`                                                |
| `GET /login/qr/create` | `key`、`qrimg=true`    | 返回 `data.qrimg`（base64），可直接用作 `<img src>`               |
| `GET /login/qr/check`  | `key`、`noCookie=true` | `800` 过期、`801` 待扫码、`802` 待确认、`803` 成功（带 `cookie`） |
| `GET /login/status`    | `cookie`               | 校验登录态，返回 `data.profile`                                   |
| `GET /user/account`    | `cookie`               | 账号与 profile                                                    |
| `GET /logout`          | `cookie`               | 退出                                                              |

所有请求都要带 `timestamp`，否则会命中 API 的缓存。这一点由 `http.ts` 统一注入。

### 3.5 数据流

```
LoginModal 打开
  → useQrLogin.start()
  → getQrKey → createQr → 展示二维码
  → 每 2s 调用 checkQr（使用 useIntervalFn）
      801/802：更新文案（802 显示「请在手机上确认」）
      800：自动重新生成二维码
      803：userStore.loginWithCookie(res.cookie) → 关闭弹窗 → 广播 user-changed
  → 弹窗关闭或组件卸载时 stop()
```

登录成功后，`stores/playlist.ts`（04）和 `stores/like.ts`（11）会 watch `isLoggedIn`，自动重新拉取数据。

### 3.6 Tauri / Rust 侧

不需要新增任何 Rust 能力，也不需要新增 capability。

### 3.7 401 处理

`http.ts` 的响应拦截器识别 `code === 301`（网易云的「需要登录」）或 `code === 401` 后：

1. 调用 `useUserStore().clear()`（在函数内部取 store，不使用任何 hook）；
2. 用 naive-ui 的 `createDiscreteApi` 弹出提示。

对同一时间段内的并发 401 做去重，只提示一次。

## 4. Windows / macOS 差异

- 二维码是 base64 图片，两个平台没有差异。
- localStorage 在 Tauri 中按 origin 存储。mac 的 origin 是 `tauri://localhost`，win 是 `http://tauri.localhost`，两者互不影响，也不需要跨平台迁移。
- 需要注意：如果将来修改 `identifier`，WebView 数据目录会随之变化，登录态会丢失。

## 6. 验收标准

- 扫码后 3 秒内完成登录，侧边栏显示头像和昵称。
- 重启应用后仍保持登录，`/login/status` 校验通过。
- 二维码过期后自动刷新，无需手动操作。
- 退出登录后，用户歌单和喜欢列表被清空。
- 在内嵌和远程两种 API 形态下都能完成登录。

## 7. 风险与待决策项

- **风控**：网易云偶尔会让二维码登录返回 `8821`（需要行为验证）。可以在 `checkQr` 中附带 `ua=pc` 参数，或者使用 API 提供的 `realIP`、`randomCNIP` 参数缓解；最终效果需要实测。
- **cookie 的安全存储**（待决策）：cookie 目前以明文存在 localStorage。是否改为使用 `tauri-plugin-stronghold`，或通过 Rust 端调用系统钥匙串（keyring crate）？建议先用 localStorage，后续再评估。
- **远程形态的安全性**：cookie 会随请求发送到远程 API 服务器。远程服务必须部署在 HTTPS 下，并由用户自己控制，需要在文档中提醒。
