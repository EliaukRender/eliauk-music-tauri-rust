# 05 全屏歌词页

## 1. 背景

### 旧实现位置

| 文件                                                                | 内容                                                                                                                |

| `src/renderer/views/LyricFullScreen/index.tsx`                      | 全屏歌词容器：自带窗口按钮（最大化、全屏、最小化）、拖拽区域、双击最大化；底部复用 `PlayControlBar`                 |
| `src/renderer/views/LyricFullScreen/components/Lyric.tsx`           | 歌词列表：gsap 做逐行高亮（`backgroundSize` 从 0 到 100%，模拟卡拉 OK 效果）、当前行字号放大、`ScrollToPlugin` 滚动 |

| `src/renderer/eventBus/modules/lyricInteraction.ts`                 | 快进快退时通知歌词修正高亮进度                                                                                      |

### 已知缺陷

- **LRC 解析不完整**：正则只匹配 `[mm:ss.xx]` 两位小数，三位毫秒（`[00:12.345]`）和一行多个时间戳（`[00:12.00][01:30.00]副歌`）都会被丢弃。
- 解析结果末尾硬塞了 8 个 `{}` 作为占位，用来撑出滚动空间，这是把数据和布局混在一起了。
- **滚动计算写死**：`scrollTo: 40 * (activeIndex - 3)` 假设行高固定 40px，多行换行或者字号变化后就会错位。
- 高亮是按「整行时长」线性动画实现的，不是真正的逐字高亮；而且动画与音频时间不同步，暂停、seek、切歌时靠事件修正，容易漂移（git 历史中「修复歌曲更新时歌词的偏移还原问题」就是这个问题）。
- 歌词来自自建后端的 `song.lyric` 字段。

## 2. 目标与范围

本期实现：

- 从控制栏封面进入全屏歌词页，展开和收起都有过渡动画
- 解析 LRC（兼容 2/3 位毫秒、一行多时间戳、元信息行）、翻译歌词 `tlyric`、罗马音 `romalrc`
- 解析**逐字歌词 YRC**，并做真正的逐字高亮
- 当前行居中滚动；用户手动滚动后，暂停自动跟随 3 秒
- 点击某行歌词 seek 到该行
- 歌词整体偏移修正（±0.5s 步进，按歌曲 id 持久化）
- 唱片机封面旋转，跟随播放状态
- 背景：封面高斯模糊 + 主色渐变

本期不做：

- 桌面歌词（独立透明置顶窗口，可以放到 M4 之后作为 07 的扩展）
- 歌词翻译引擎

## 3. 方案设计

### 3.1 解析

新增 `src/utils/lyric/parse-lrc.ts` 和 `parse-yrc.ts`，都是纯函数，并配单元测试。

```ts
type LyricWord = { start: number; duration: number; text: string } // 单位：秒
type LyricLine = {
  start: number
  end: number
  text: string
  trans?: string
  roma?: string
  words?: LyricWord[]
}
```

- **LRC**：正则 `/\[(\d{1,2}):(\d{1,2})(?:[.:](\d{1,3}))?\]/g` 用全局匹配提取一行中的全部时间戳；毫秒按位数归一化；最后按 `start` 排序。`end` 取下一行的 `start`，最后一行取歌曲时长。
- **元信息行**：实测 `/lyric/new` 返回的 `lrc.lyric` 开头有 JSON 行，例如 `{"t":0,"c":[{"tx":"作词: "},{"tx":"黄家驹",...}]}`。以 `{` 开头的行要按 JSON 解析，把 `c[].tx` 拼成文本，作为「作词/作曲」信息行。
- **YRC**：格式为 `[行起始ms,行时长ms](字起始ms,字时长ms,0)字...`，解析出 `words`。
- **合并翻译**：按 `start` 做容差 0.1s 的匹配，把 `tlyric` 合并进对应行。

### 3.3 同步方案（替代 gsap 时间线）

- 每帧用 `useRafFn` 读取 `engine.currentTime + offset`。
- `activeIndex` 通过二分查找得到。只在它变化时更新响应式状态，避免每帧触发 Vue diff。
- **逐字高亮**：只对当前行设置 CSS 变量 `--progress`（0 到 1），样式用 `background-clip: text` + `linear-gradient` 实现。YRC 歌词按字计算进度，LRC 按行计算进度。
- 这样暂停、seek、切歌时**不需要任何修正事件**，因为进度始终从音频时间派生，从根上解决了旧项目的漂移问题。
- **滚动**：`scroller.scrollTo({ top: line.offsetTop - scroller.clientHeight / 2 + line.clientHeight / 2, behavior: 'smooth' })`，用实际 DOM 尺寸计算，不再写死行高。上下留白用 CSS `padding-block: 50%` 实现，替代旧项目的 8 个空对象。

### 3.4 Store 设计：`stores/lyric.ts`

```ts
state: {
  songId: number | null
  lines: LyricLine[]
  hasYrc: boolean
  status: 'idle' | 'loading' | 'ready' | 'empty' | 'error'
  offsets: Record<number, number>   // 持久化；songId 到秒，只保存非 0 值
  showTrans: boolean                // 持久化
  showRoma: boolean                 // 持久化
  visible: boolean                  // 全屏歌词是否展开
}
actions: load(songId)（watch player.currentId 触发）、adjustOffset(delta)、resetOffset()
```

### 3.5 唱片机与背景

- JukeBox 改用 CSS `animation: spin 20s linear infinite`，用 `animation-play-state` 跟随 `isPlaying`，不再需要 gsap。
- 旧项目的唱片素材 `changpianji.png` 可以复用；中心放封面，使用 `picUrl?param=400y400` 请求缩略图。
- 背景主色：用 canvas 从 64×64 的缩略封面中提取主色。封面 CDN 已确认带 CORS 头，需要设置 `crossOrigin`。

### 3.6 Tauri / Rust 侧

- 全屏歌词页里的窗口按钮复用骨架的 `WindowControls.vue` 和 `services/tauri/window.ts`。
- 全屏或退出全屏需要 capability `core:window:allow-set-fullscreen` 和 `core:window:allow-is-fullscreen`。

## 4. Windows / macOS 差异

- **mac**：全屏歌词页展开后红绿灯依然可见（Overlay 标题栏），页面左上角要给它留出安全区。进入系统全屏后红绿灯会自动隐藏。
- **win**：页面右上角要显示 `WindowControls`；整个顶部 40px 设置 `data-tauri-drag-region`。
- `background-clip: text` 在 WKWebView 中需要加 `-webkit-` 前缀（Tailwind v4 会自动加）。
- 模糊背景在 Windows 集显机器上比较耗 GPU：使用 `filter: blur()` 作用在静态缩略图上，不要使用 `backdrop-filter`。

## 6. 验收标准

- 有 YRC 的歌曲逐字高亮与演唱对齐，误差不超过 100ms。
- 反复暂停、seek 20 次、切歌后，高亮都不漂移。
- 窗口缩放和字号变化后，当前行仍然保持居中。
- 纯音乐或无歌词的歌曲显示「纯音乐，请欣赏」或「暂无歌词」。
- 偏移调节在重启后仍然生效。

## 7. 风险与待决策项

- 桌面歌词是否纳入后续规划（待决策）。
