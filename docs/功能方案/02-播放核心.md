### 现有行为

- 播放、暂停、上一曲、下一曲
- 快进和快退，固定 ±5 秒
- 三种播放模式、音量（含静音）、进度拖拽
- 双击歌曲切歌
- 第一次播放时才创建 `AudioContext` 和 `AnalyserNode`，用于频谱

### 已知缺陷（迁移时一并修复）

1. **单曲时随机播放报错**：`getRandomSong` 在只有一首歌时返回数字 `0`，调用方接着读 `nextSong.songId` 就会报错。另外「重新随机」只执行一次，仍可能随机到当前这首。
2. **播放队列被覆盖**：`playAudio` 成功后总是调用 `setActiveSongList(mainMenu.curSheetSongList)`，会覆盖 `playSong` 传入的 `songList`。在 A 歌单开始播放、再切到 B 歌单浏览时，一切歌队列就变成了 B。
3. **快退会暂停**：`decreaseCurrentTime` 先调用了 `pauseAudio()`，后退后歌曲停在暂停状态，而且 `lastTime <= 0` 分支没有同步 store。
4. **音量为 0 失效**：`playAudio` 里 `audio.volume = volume || ...`，0 是假值，会被默认值覆盖。
5. **加载锁可能卡死**：`isLoadingSong` 由调用方置 true、由 `play()` 的 then/catch 置 false。只要中途有 return（比如 `nextSong` 为 undefined）锁就永远不会释放。并且没有请求竞态保护，快速连续切歌时，先发的请求可能后返回并覆盖当前歌曲。
6. **高频 dispatch**：`timeupdate` 每次都 dispatch 到全局 store，引起整棵订阅树重渲染。
7. **URL 失效**：歌曲 URL 直接来自自建后端，没有过期处理。网易云的 URL 带时间戳签名，会在约 20 分钟后失效。

## 2. 目标与范围

本期实现：

- 播放、暂停、上一曲、下一曲（手动 / 自然结束）、±5 秒快进快退、三种播放模式
- 音量与静音，并持久化
- 进度展示与拖拽
- 双击歌曲播放、当前歌曲高亮
- 歌曲 URL 获取、音质选择、试听片段提示、URL 过期后自动重新获取
- 冷启动恢复上次的队列和歌曲（不自动播放）
- 暴露 AnalyserNode 给频谱模块（06）

本期不做：

- 均衡器 EQ
- 无缝播放和淡入淡出（预留 `crossfade` 设置项）
- 播放速率 UI（旧项目有 state 但没有 UI，保留 store 字段）
- 本地音乐、下载、解灰（unblock）

## 3. 方案设计

### 3.1 音频引擎选型：原生 `HTMLAudioElement` + Web Audio

| 维度                 | 原生 Audio + Web Audio                                                 | howler.js                                                                                                                                     |
| -------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 频谱                 | 使用 `createMediaElementSource(audio)` 接入 AnalyserNode，这是标准做法 | html5 模式下需要取 `sound._node` 私有字段再接 Web Audio（参考项目 `eqService.ts` 就是这么做的）；Web Audio 模式要先完整下载解码，不能边下边播 |
| 流式播放、Range 请求 | 原生支持                                                               | html5 模式支持                                                                                                                                |
| 体积                 | 0                                                                      | 约 36 KB                                                                                                                                      |
| 多音源、精灵         | 不需要                                                                 | 用不上                                                                                                                                        |

**结论：使用原生 `HTMLAudioElement`，把它接入一个长期存在的 `AudioContext`：`source → analyser → gain → destination`。** 不引入 howler。

两个关键约束：

- `createMediaElementSource` 对同一个 element 只能调用一次，所以整个应用只保留一个 audio element，切歌时只改 `src`。
- `AudioContext` 要在首次用户手势时创建或 `resume()`。WKWebView 和 WebView2 都有自动播放策略。

### 3.2 跨域与音频 URL（已实测）

2026-09 实测，`/song/url/v1` 返回的 `http://m7xx.music.126.net/...` 地址：

- 响应头带 `Access-Control-Allow-Origin: *`，支持 `Range`（206 Partial Content）；
- 替换为 `https://` 后同样可以访问，也同样带 CORS 头。

因此：

- audio element 要设置 `crossOrigin = 'anonymous'`。否则媒体会被视为跨域不透明资源，AnalyserNode 只能拿到全 0 数据。
- **统一把 URL 升级为 `https://`**（在 `api/adapters/song.ts` 中处理）。原因是 macOS 页面源 `tauri://localhost` 属于安全上下文，http 媒体属于混合内容，WKWebView 可能拦截或自动升级，行为不稳定；Windows 页面源 `http://tauri.localhost` 本身不受影响。统一升级后，两个平台的行为一致。
- 如果个别 CDN 节点不带 CORS 头，按 06 文档中的「Rust 流式代理」兜底方案处理。

### 3.4 Store 设计：`stores/player.ts`

```ts
const PlayMode = { Sequence: 'sequence', Shuffle: 'shuffle', RepeatOne: 'repeat-one' } as const
type PlayMode = (typeof PlayMode)[keyof typeof PlayMode]
type SoundLevel = 'standard' | 'higher' | 'exhigh' | 'lossless' | 'hires'

state: {
  queue: Song[]                 // 播放队列（持久化 id，冷启动时补全）
  currentId: number | null      // 持久化
  status: 'idle' | 'loading' | 'playing' | 'paused' | 'error'
  duration: number
  volume: number                // 0-100，持久化
  muted: boolean                // 持久化
  mode: PlayMode                // 持久化
  level: SoundLevel             // 持久化；未登录或非 VIP 时降级
  trial: { start: number; end: number } | null  // 试听片段信息
  lastPosition: number          // 持久化；低频写入（暂停、切歌、beforeunload 时）
}
getters: currentSong, currentIndex, isPlaying
actions: {
  playSongs(songs: Song[], startId?: number)  // 替换队列并播放（修复缺陷 2：显式传入队列）
  playSong(song: Song)                        // 队列中已有则跳过去，没有则插到当前歌曲之后
  toggle()
  next(manual = true)
  prev()
  seek(t)
  seekBy(delta)                               // ±5s；只修改 currentTime，不改变播放状态（修复缺陷 3）
  setVolume(v)
  toggleMute()
  setMode(m)
  restore()                                   // 冷启动恢复
}
```

**竞态控制（修复缺陷 5）**：`loadAndPlay(id)` 内部维护自增的 `requestSeq`，每个异步步骤返回后都比较 seq，过期就丢弃。不再使用布尔锁，所以不存在「锁未释放」的问题。

**高频字段（修复缺陷 6）**：`currentTime` 不放进 store。进度条组件通过 `usePlayerProgress` 直接读取 engine。歌词页也通过这个 composable 订阅。

### 3.5 接口

| 接口               | 关键参数                                                                 | 说明                                                                                  |
| ------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `GET /song/url/v1` | `id`、`level`（`standard` / `higher` / `exhigh` / `lossless` / `hires`） | 返回 `data[0].url`、`br`、`size`、`freeTrialInfo`；`url` 为 null 表示无版权或需要 VIP |
| `GET /song/detail` | `ids`（逗号分隔）                                                        | 补全队列元数据                                                                        |
| `GET /check/music` | `id`                                                                     | 可选，播放前检查可用性                                                                |

补充说明：

- **试听片段**：实测匿名状态下，VIP 歌曲会返回 `freeTrialInfo: { start: 0, end: 35 }`。播放器在 UI 上显示「试听」标签，时长以 trial 为准；播放到 trial 结束时触发 ended。
- **URL 过期（修复缺陷 7）**：audio 的 `error` 事件如果是 `MEDIA_ERR_NETWORK` 或 403，就重新请求 URL 一次，然后从原位置 seek 继续播放。同时，暂停超过 15 分钟后再恢复播放时，先主动刷新 URL。

### 3.6 数据流

```
SongList 双击
  → player.playSongs(list, song.id)
  → queue = list; currentId = id; status = 'loading'
  → getSongUrl(id, level)（seq 校验）→ engine.load(https url) → engine.play()
  → engine 'playing' → status = 'playing'
  → engine 'ended' → player.next(false) → play-mode.pickNext
PlayerBar 进度条 ← usePlayerProgress（rAF 读取 engine.currentTime）
```

### 3.7 Tauri / Rust 侧

- 不需要新增 command。
- 媒体会话（系统媒体键、mac 控制中心的「正在播放」）归到 08 文档处理。
- CSP 需要允许 `media-src https://*.music.126.net http://*.music.126.net blob:`，以及 `img-src https://*.music.126.net`（封面）。在 `tauri.conf.json` 的 `app.security.csp` 中配置。

## 4. Windows / macOS 差异

| 项目         | macOS（WKWebView）                                     | Windows（WebView2 / Chromium） | 处理                                                                      |
| ------------ | ------------------------------------------------------ | ------------------------------ | ------------------------------------------------------------------------- |
| 自动播放策略 | 首次播放需要用户手势                                   | 较宽松                         | 统一在首次点击时 `ctx.resume()`                                           |
| http 媒体    | 页面源为安全上下文，存在混合内容风险                   | 页面源是 http，不受影响        | 统一升级为 https                                                          |
| 支持的格式   | 不支持 FLAC 以外的部分无损格式；FLAC 在 macOS 11+ 支持 | 都支持                         | 选择 `lossless` / `hires` 时让 API 返回 flac；播放失败时自动降到 `exhigh` |
| 后台节流     | 窗口最小化后 rAF 暂停                                  | 同样暂停                       | 进度只用于展示，不影响播放；ended 事件照常触发                            |

## 6. 验收标准

- 双击任意歌曲 1 秒内开始出声（网络正常时）。
- 快速连续点击下一首 10 次，最终播放的是最后一次点击对应的歌曲，状态不会卡在 loading。
- 随机模式下队列只有 1 首时不报错；队列有 N 首时，连续 N 次下一首不重复。
- 快退后保持原来的播放状态。
- 音量设为 0 后切歌仍然静音；重启后音量和模式都能恢复。
- 暂停 30 分钟后继续播放能自动刷新 URL，不报错。
- VIP 歌曲在未登录状态下显示「试听」，35 秒后自动切到下一首。
- 在 macOS 和 Windows 上都能播放，并且 AnalyserNode 数据不为全 0（为 06 频谱做前置验证）。

## 7. 风险与待决策项

- **无版权歌曲**（待决策）：`url` 为 null 时是跳过并提示，还是接入解灰？
  - 参考项目 AlgerMusicPlayer 的做法是解灰，默认开启（音源：咪咕、酷狗、pyncmd），设置页可以关闭。
  - 我们使用的 API 已内置解灰：`/song/url/v1?unblock=true`，或 `/song/url/match?id=&source=` 指定音源，由 `@neteasecloudmusicapienhanced/unblockmusic-utils` 实现。不需要额外依赖，内嵌和远程两种形态都可用。
  - 解灰涉及第三方音源的合规问题。
- **默认音质**（待决策）：未登录默认 `standard`，登录后默认 `exhigh`，VIP 可选 `lossless`。
- **个别 CDN 节点不带 CORS**：概率低，但会导致频谱静音。兜底方案见 06。
- **WebView2 版本差异**：Windows 10 旧系统可能缺少 WebView2 运行时，由安装包的 `webviewInstallMode` 处理（属于骨架配置）。
