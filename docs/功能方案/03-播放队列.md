# 03 播放队列弹窗

## 1. 背景

### 旧实现位置

- `src/renderer/views/PlayerControlBar/components/ActiveSongEntry.tsx`：控制栏上的入口图标，以及用自绘 Drawer 展示的「当前播放歌曲列表」。
- `src/renderer/views/components/SongItem/SongItemForActive*`：队列中的单项组件。
- `src/renderer/hooks/useScrollSongVisible.ts`：抽屉打开后，把当前歌曲滚动到可视区域。
- `src/renderer/store/actions/PlayerControlActions.ts#deleteSongFromSongList`：从队列删除歌曲。

### 已知缺陷

- 删除正在播放的歌曲后，只切换了 `activeSongId`，播放逻辑是 `// todo`，**音频还在播放被删除的那首歌**。
- 只剩一首歌时不允许删除（体验上可以改为「清空队列」）。
- 滚动定位依赖 `setTimeout(100)` 的标志位切换，比较脆弱。
- 没有「清空」「下一首播放」「队列持久化」。

## 2. 目标与范围

本期实现：

- 右侧抽屉展示播放队列：歌曲总数、当前歌曲高亮、打开时自动定位到当前歌曲
- 双击播放队列中的某一首
- 从队列中移除单首；移除当前歌曲时自动播放下一首；队列清空后停止播放
- 清空队列
- 「下一首播放」的插入能力（右键菜单调用，见 09）

本期不做：

- ~~拖拽排序~~、~~播放历史~~：已在后续迭代实现，见第 8 节

## 3. 方案设计

### 3.1 文件划分

| 文件                                         | 职责                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| `src/components/player/PlayQueueDrawer.vue`  | naive-ui `NDrawer`（placement 为 right，宽 380），标题栏包含「播放队列 (N)」和清空按钮 |
| `src/components/player/QueueItem.vue`        | 单项：序号或正在播放动画、歌名、歌手、时长；悬停时显示删除按钮                         |
| `src/components/player/QueueEntryButton.vue` | 控制栏入口按钮，图标 `i-ri-play-list-2-line`                                           |

列表使用 naive-ui 的 `NVirtualList`（或 `useVirtualList`），因为「播放全部」歌单可能有数千首。定位使用 `virtualListRef.scrollTo({ index, position: 'center' })`，在抽屉的 `@after-enter` 回调中调用，不再依赖 setTimeout。

### 3.2 Store 动作（补充到 `stores/player/`）

```ts
removeFromQueue(id: number): void
  // 删除的不是当前歌曲：直接移除
  // 删除的是当前歌曲：先计算同位置的下一首（没有就取上一首），移除后如果原来在播放则 loadAndPlay，否则只切换 currentId
  // 删除后队列为空：engine.stop()，currentId = null，status = 'idle'
clearQueue(): void
insertNext(songs: Song[]): void   // 去重后插到 currentIndex + 1
```

UI 状态 `queueDrawerVisible` 放在 `stores/app.ts`，这样快捷键和 mini 窗口也能打开抽屉。

### 3.3 接口

不需要新增接口。冷启动恢复队列时使用 `/song/detail`（见 02）。

### 3.4 数据流

```
QueueEntryButton 点击 → appStore.queueDrawerVisible = true
  → NDrawer after-enter → scrollTo(currentIndex)
QueueItem 双击 → player.playSong(song)（队列中已存在，直接跳到这首）
QueueItem 删除 → player.removeFromQueue(id)
```

### 3.5 Tauri / Rust 侧

无。

## 4. Windows / macOS 差异

- 抽屉的遮罩层不能覆盖标题栏拖拽区域。mac 的 Overlay 标题栏下红绿灯区域必须保持可点击，所以要设置 NDrawer 的 `to` 目标，或者给内容区加上 `top` 偏移（标题栏高度 `--titlebar-height`）。
- 滚动条样式：Windows 默认滚动条较粗，需要全局统一细滚动条样式（`::-webkit-scrollbar` 对 WebView2 和 WKWebView 都有效）。

## 6. 验收标准

- 打开抽屉后，当前歌曲位于视口中部。在 3000 首的队列下打开抽屉不卡顿（首帧小于 100ms）。
- 删除正在播放的歌曲后，立刻播放下一首，被删除的歌曲不再发声。
- 删除最后一首后，播放器进入 idle，控制栏显示空状态。
- 清空队列后重启应用，队列仍为空。

## 8. 拖拽排序与播放历史（2026-10）

### 8.1 拖拽排序

- **不使用 `vue-draggable-plus`**：队列是虚拟列表，滚动时 DOM 节点会被回收复用，SortableJS 这类直接搬动 DOM 的库会与虚拟列表冲突。改为 `composables/useListDragSort.ts`：按指针位置和固定行高计算插入位置，只渲染一条插入线，松手时修改数据；靠近上下边缘自动滚动，Esc 取消。
- 从行首的把手发起拖拽，不影响双击播放与右键菜单。
- `stores/player/queue.ts` 新增 `moveInQueue(id, toIndex)`，`toIndex` 为移除自身后的下标。随机模式下同步调整 `shuffleOrder`，让歌曲紧跟新位置的前一首，拖到当前歌曲下方即为下一首。
- mini 窗口按队列 id 序列推送，排序后自动同步，无需额外处理。
- 队列右键菜单新增「下一首播放」（当前歌曲不显示）。

### 8.2 播放历史

- 队列抽屉分为「播放队列 / 最近播放」两个标签，每次打开回到播放队列。
- `stores/history.ts`：最近播放在前，重复播放移到最前，上限 500 首；持久化完整的 `Song`，不需要冷启动补全；只存本地，不区分账号。
- `composables/app/usePlayHistory.ts`（挂在 `DefaultLayout`，mini 窗口不写入）：歌曲真正开始播放时记录，暂停后继续、单曲循环重播不重复记录。
- 列表项双击播放（插到当前歌曲之后）、右键为歌曲通用菜单、悬停可删除单条；清空需要确认。
