# 07 mini 播放器窗口

## 1. 背景

### 旧实现位置

| 文件                                                                                                 | 内容                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/main/main.ts`                                                                                   | 启动时就创建 mini 窗口，配置为 330×290、`frame:false`、`transparent`、`alwaysOnTop`、`skipTaskbar`，加载 `#/mini-player`，然后立即 `minimize()` 并放到屏幕右下角 |
| `src/main/ipcMain/constant/index.ts`                                                                 | `Win_Width=330`、`Win_Height=290`、`Win_Header_Height=90`                                                                                                        |
| `src/main/ipcMain/miniPlayerWin/winUiHandler.ts`                                                     | 拖拽定位（渲染进程算坐标后调用 `setPosition`，并做屏幕边界判断）、修改窗口高度（折叠或展开列表）                                                                 |
| `src/main/ipcMain/mainWin/winUihandler.ts`                                                           | `Show_Hidden_Mini_Player` 显示或隐藏；`Update_Mini_Player_Data` 在主窗口和 mini 窗口之间转发数据                                                                 |
| `src/main/ipcMain/mainWin/musicControlHandler.ts` + `ipcRenderer/mainWindow/musicControlListener.ts` | mini 的控制指令经主进程转发到主窗口                                                                                                                              |
| `src/renderer/views/MiniPlayer/MiniPlayer.tsx`                                                       | 封面、歌名、歌手；悬停时显示按钮组（喜欢、上一首、播放/暂停、下一首、列表折叠、关闭）；下方是可折叠的队列列表                                                    |
| `src/renderer/hooks/useUpdateMiniPlayerData.ts`                                                      | 主窗口监听 `activeSongId`、`activeSongList`、`isPlaying`，每次变化都**全量**推送给 mini 窗口                                                                     |

### 已知缺陷

- mini 窗口在启动时就创建，并常驻内存，即使用户从不打开它。
- 每次状态变化都全量推送 `activeSongList`，队列大的时候开销很高。
- mini 窗口的 `ipcRenderer.on` 没有取消订阅；每次 `createWindow` 都会重复注册 `ipcMain.handle`（macOS 的 activate 场景会直接抛错）。
- 「喜欢」按钮调用的 `miniPlayerEmitter.likeSong` 没有实际效果。
- 拖拽用自定义 IPC 实现，多显示器的情况没有处理（代码中留有 todo）。

## 2. 目标与范围

本期实现：

- 懒创建：第一次打开时才创建窗口；关闭时 hide，不销毁
- 置顶、跳过任务栏、不可缩放、首次出现在主屏右下角，之后记住位置
- 展示封面、歌名、歌手；按钮组：喜欢（接入 11）、上一首、播放/暂停、下一首、展开或折叠队列、返回主窗口、关闭
- 队列列表：双击播放，当前歌曲高亮
- 状态同步：主窗口作为唯一数据源，mini 窗口只负责展示和转发指令
- 从托盘、主窗口按钮、快捷键都能打开

本期不做：

- 歌词、频谱在 mini 窗口中的展示
- mini 窗口独立播放（音频始终只在主窗口）

## 3. 方案设计

### 3.1 窗口创建：放在 Rust 端

在 `src-tauri/src/windows/mini.rs` 中提供 command `toggle_mini_player`：

```rust
// 已存在则 show/hide 切换；不存在则创建
WebviewWindowBuilder::new(app, "mini", WebviewUrl::App("index.html#/mini".into()))
    .inner_size(330.0, 290.0).resizable(false).always_on_top(true)
    .skip_taskbar(true).visible(false)
    // 平台差异见第 4 节
```

之所以放在 Rust 端创建，而不是前端 `new WebviewWindow()`：

1. 托盘、全局快捷键这些 Rust 侧入口可以直接调用；
2. 平台相关的窗口外观（mac 隐藏红绿灯）需要调用原生 API；
3. 前端不需要 `core:webview:allow-create-webview-window` 这个较大的权限。

- **首次位置**：用 `primary_monitor()` 的 work area 计算右下角（右边距 24、下边距 24），并且按监视器的 scale factor 换算。
- **记住位置**：`tauri-plugin-window-state` 已经在骨架中启用，它按窗口 label 记录，mini 窗口会自动生效。需要把 `StateFlags` 设为只记录 `POSITION`，不记录尺寸，因为尺寸由折叠状态决定。
- **关闭**：拦截 `CloseRequested` 事件，改为 hide。

### 3.2 路由与页面

- 路由 `/mini`，加载独立布局 `src/layouts/MiniLayout.vue`：不含侧边栏和控制栏。
- 页面 `src/views/mini/MiniPlayerView.vue`，子组件 `components/{MiniHeader,MiniQueue}.vue`。
- `main.ts` 中根据 `getCurrentWindow().label` 决定是否初始化播放器相关模块：mini 窗口**不创建 audio-engine**。

### 3.3 跨窗口状态同步（Tauri 事件）

事件名定义在 `src/constants/events.ts`：

```ts
export const AppEvent = {
  PlayerSnapshot: 'player://snapshot', // 主窗口发给 mini：完整快照（首次或 mini 请求时）
  PlayerPatch: 'player://patch', // 主窗口发给 mini：增量字段
  PlayerCommand: 'player://command', // mini、托盘发给主窗口：控制指令
  MiniReady: 'mini://ready', // mini 发给主窗口：请求快照
} as const
```

- **主窗口**：`src/services/tauri/player-bridge.ts`。watch player store 中的轻量字段（`currentId`、`status`、`liked`、`mode`），用 `emitTo('mini', PlayerPatch, patch)` 推送。队列只在 `queueVersion` 变化时发送，并且只发 `{ id, name, artists, coverUrl }` 精简字段。收到 `MiniReady` 时发送完整快照。
- **mini 窗口**：`src/stores/mini.ts`，只读镜像，不持久化。挂载后先 `listen` 再 `emit(MiniReady)`，避免错过快照。控制按钮调用 `emitTo('main', PlayerCommand, { type: 'next' })`。
- **托盘**（08）同样通过 `PlayerCommand` 发给主窗口，指令入口统一。
- 所有 `listen` 返回的 unlisten 函数都在 `onUnmounted` 中调用（修复旧的监听泄漏）。

### 3.4 折叠列表

- 展开时窗口高度 290，折叠时 90。用 `getCurrentWindow().setSize(new LogicalSize(330, h))` 实现，需要 capability `core:window:allow-set-size`，只授权给 `mini` 窗口。
- 顺序：折叠时先做内容动画（CSS transition 高度 200ms），再缩小窗口；展开时先放大窗口，再做内容动画。沿用旧项目的思路。
- 拖拽：头部区域加 `data-tauri-drag-region`，需要 capability `core:window:allow-start-dragging`，**不再自己计算坐标**，多显示器由系统处理。

### 3.5 capabilities

新增 `src-tauri/capabilities/mini.json`：

```json
{
  "identifier": "mini",
  "windows": ["mini"],
  "permissions": [
    "core:default",
    "core:event:default",
    "core:window:allow-start-dragging",
    "core:window:allow-set-size",
    "core:window:allow-hide"
  ]
}
```

主窗口的 `default.json` 需要加入 `core:event:default`，并允许调用 `toggle_mini_player` command（自定义 command 默认允许，如果启用了 app 级 ACL 就需要在 permissions 中声明）。

## 4. Windows / macOS 差异

| 项目         | macOS                                                                              | Windows                                                                                       | 处理                                                                                                                                                                                                                                                                        |
| ------------ | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 透明与圆角   | 真正透明需要 `macOSPrivateApi: true`，这会阻止上架 Mac App Store，并且依赖私有 API | `transparent(true)` 可用，但在 Win10 上无边框透明窗口没有阴影，Win11 上与 `shadow` 有兼容问题 | **不使用透明窗口**，改为「原生圆角」：mac 用 `decorations(true)` + `title_bar_style(Overlay)` + `hidden_title(true)`，再通过 objc2 把三个 `standardWindowButton` 隐藏，得到系统圆角和阴影；win 用 `decorations(false)` + `shadow(true)`，Win11 自动圆角，Win10 为直角带阴影 |
| 置顶         | `always_on_top` 在全屏 Space 中不可见                                              | 正常                                                                                          | mac 额外设置 `visible_on_all_workspaces(true)`，让它在各个 Space 都显示                                                                                                                                                                                                     |
| 跳过任务栏   | `skip_taskbar` 在 mac 无效（不显示在 Dock 需要 `ActivationPolicy`）                | 生效                                                                                          | mac 不需要处理，mini 窗口不会单独出现在 Dock                                                                                                                                                                                                                                |
| 焦点         | 点击 mini 窗口时应用会被激活，主窗口可能被带到前台                                 | 不会                                                                                          | mac 使用 `focused(false)` 创建，并且 show 时不调用 `set_focus`                                                                                                                                                                                                              |
| 多显示器位置 | 使用 window-state 恢复；显示器被拔掉时                                             | 同左                                                                                          | 恢复后检查位置是否落在任意 monitor 范围内，不在就回到主屏右下角                                                                                                                                                                                                             |

已决策：不使用透明窗口，采用上表的原生圆角方案。

## 5. 实施步骤

- [x] `src-tauri/src/mini_window.rs`：`toggle_mini_player`（async：Windows 上同步 command 创建窗口会死锁）、`resize_mini_player`、首次定位到主屏工作区右下角、close 时 hide；mac 隐藏红绿灯在 `src-tauri/src/macos.rs`（`objc2-app-kit`）。Tauri 没有暴露隐藏按钮的接口，所以 crate 级 `unsafe_code` 从 `forbid` 改为 `deny`，只在该模块内放开
  - Windows 下 mini 窗口必须设置与主窗口相同的 `additional_browser_args`，否则 WebView2 环境参数不一致会导致创建失败
- [x] `src-tauri/src/lib.rs`：注册 command；window-state 对 mini 使用 `skip_initial_state`，创建后只 `restore_state(POSITION)`（插件会丢弃落在已拔出显示器上的位置）
- [x] `src-tauri/capabilities/mini.json`（`core:default` + 拖拽 + 隐藏；改尺寸走自定义 command，不再需要 `allow-set-size`）；`default.json` 无需改动
- [x] `src/constants/events.ts`：`MiniState`（轻量、频繁）与 `MiniQueue`（仅队列变化时）分开推送，替代快照 + patch；mini 指令新增 `play-song`、`toggle-like`
- [x] 主窗口侧：`composables/useMiniBridge.ts`（收到 `MiniReady` 前不推送）；指令处理复用 `useSystemBridge`
- [x] `src/stores/mini.ts`（镜像，不持久化）
- [x] 不走路由：`main.ts` 按窗口 label 分流，mini 挂载独立的 `MiniApp.vue`，不加载主界面、路由和 player store。原因：两个窗口同源共享 localStorage，mini 里如果也实例化 player store，它的持久化可能覆盖主窗口的状态。开发时可用 `?window=mini` 在浏览器中调试
- [x] `src/MiniApp.vue`（监听 storage 事件同步主题）、`src/views/mini/MiniPlayerView.vue`、`components/MiniQueue.vue`
- [x] 入口：控制栏按钮、托盘菜单「mini 播放器」、全局快捷键（默认 `CommandOrControl+Alt+M`）

### 实施记录

- 窗口尺寸：宽 340，折叠 96、展开 400（逻辑像素）。展开时先放大窗口再显示列表，折叠时反过来。
- 已在本机启动 Tauri 应用确认初始化无报错；mini 窗口的外观（圆角、阴影、红绿灯隐藏）、置顶和位置记忆需要手工验证，Windows 由 CI 编译。

## 6. 验收标准

- 应用启动时不创建 mini 窗口，进程数不增加。
- 打开 mini 窗口后 300ms 内显示当前歌曲；主窗口切歌后 mini 窗口 100ms 内同步。
- 在 mini 窗口中执行播放、暂停、上一首、下一首、双击队列歌曲，主窗口都能正确响应。
- mini 窗口拖到副屏后关闭再打开，位置保持；拔掉副屏后再打开，窗口回到主屏右下角。
- 在 mac 上主窗口处于全屏 Space 时，mini 窗口仍然可见并置顶。
- 在 mac 和 Win11 上都有圆角和阴影，没有白边。

## 7. 风险与待决策项

- **是否需要真正的透明异形窗口**（已决策：不透明）：不开启 `macOSPrivateApi`，用原生圆角窗口替代旧项目头部的「透明 + 非透明」分层视觉。
- objc2 隐藏红绿灯需要维护少量 unsafe 代码，要跟随 Tauri 和 objc2 的版本升级。
- 两个窗口共用同一个前端 bundle，mini 窗口首屏会加载完整的 JS。可以在路由层做懒加载切分，保证 mini 窗口不加载主界面的 chunk。
