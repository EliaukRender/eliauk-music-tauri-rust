# 09 右键菜单

## 1. 背景

### 旧实现位置

| 文件                                                                     | 内容                                                                                       |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `src/renderer/views/ContextMenu/ContextMenu.tsx`、`ContextMenuStyles.ts` | 自绘菜单浮层，位置取 `x+15`、`y-10`；点击外部时关闭（`useClickOutside`）                   |
| `src/renderer/hooks/useContextMenu.ts`                                   | 通过 EventBus（`EventBusEnum.ContextMenu`）接收菜单项和坐标                                |
| `src/renderer/views/Layout/index.tsx`                                    | 全局 `onContextMenu={e => e.preventDefault()}`，禁用浏览器默认菜单；挂载唯一的 ContextMenu |
| `src/renderer/views/components/MenuItem/SheetMenu.tsx`                   | 歌单菜单：播放（随机一首）、删除歌单（默认歌单禁用）、重命名（空实现）                     |
| `src/renderer/views/components/SongItem/SongItemForSheet.tsx`            | 歌曲菜单：播放、删除                                                                       |
| `src/renderer/types/contextMenu.d.ts`                                    | `IContextMenuItem { label, icon, disabled, onClick }`                                      |

### 已知缺陷

- 没有做边界检测：在窗口右侧或底部右键时，菜单会超出窗口被截断。
- 不支持子菜单（例如「添加到歌单 > 歌单列表」）。
- 滚动、窗口失焦、按 Esc 时菜单不会关闭。
- 菜单项的 `onClick` 闭包通过 EventBus 传递，类型是 any。

## 2. 目标与范围

本期实现：

- 歌曲项菜单：播放、下一首播放（03）、添加到歌单 ▸（子菜单，列出 04 的用户创建歌单 + 新建歌单）、从当前歌单移除（仅在自己创建的歌单详情页显示）、喜欢或取消喜欢（11）、复制歌曲链接
- 歌单侧边栏项菜单：播放全部、重命名、删除（「我喜欢的音乐」和收藏的歌单不显示删除）
- 队列项菜单：播放、从队列移除
- 全局禁用 WebView 的默认右键菜单（开发环境保留，方便检查元素）

本期不做：

- 多选歌曲的批量菜单

## 3. 方案设计

### 3.1 方案对比

| 维度         | A. Tauri 原生菜单 `Menu.popup()`                       | B. 自绘（naive-ui `NDropdown`，`trigger="manual"` + `x`/`y`） |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------- |
| 外观         | 系统原生，mac 和 win 各自风格，自动适配深色模式        | 与应用主题一致，可以放图标、自定义样式                        |
| 边界与子菜单 | 系统处理，不会被窗口截断，可以超出窗口                 | NDropdown 支持子菜单和边界翻转，但不能超出窗口                |
| 动态内容     | 每次右键都要构建 Menu（需要异步 IPC），有 10–30ms 延迟 | 同步，没有延迟                                                |
| 图标         | 只支持图片或原生图标，不支持 iconify                   | 支持 iconify 组件                                             |
| 焦点与关闭   | 系统管理                                               | 需要自己处理滚动、失焦、Esc（NDropdown 已经处理了大部分）     |
| 权限         | 需要 capability `core:menu:default`                    | 不需要                                                        |

**结论：采用 A（Tauri 原生菜单）**：

- 桌面应用右键菜单使用原生样式更符合平台预期，尤其在 mac 上；
- 边界、子菜单、键盘导航都由系统处理，直接解决旧项目的截断问题；
- 使用 `@tauri-apps/api/menu` 在前端构建，不需要写 Rust 代码。

同时保留一个自绘的兜底实现，封装在同一个接口后面。如果后续遇到原生菜单的能力限制（比如需要显示歌曲封面），可以切换到 B。

### 3.2 统一接口

`src/composables/useContextMenu.ts`：

```ts
type MenuAction =
  | {
      type: 'item'
      id: string
      label: string
      enabled?: boolean
      accelerator?: string
      action: () => void
    }
  | { type: 'submenu'; label: string; items: MenuAction[] }
  | { type: 'separator' }

export function useContextMenu() {
  async function show(items: MenuAction[], event: MouseEvent): Promise<void>
  // 内部：event.preventDefault()，然后转换成 Menu.new({ items: [MenuItem/Submenu/PredefinedMenuItem.separator] })，再 menu.popup()
}
```

各业务菜单的构建函数放在 `src/features/context-menus/{song-menu,playlist-menu,queue-menu}.ts`：接收上下文（`song`、`playlistId`、`isOwner`），返回 `MenuAction[]`。**菜单的内容与展示解耦**，也便于写单元测试。

### 3.3 全局禁用默认菜单

在 `main.ts` 中：

```ts
if (!import.meta.env.DEV) window.addEventListener('contextmenu', (e) => e.preventDefault())
```

输入框需要保留系统的「剪切 / 复制 / 粘贴」菜单，所以 target 是 `input`、`textarea` 时放行。

### 3.4 capabilities

在 `default.json` 和 `mini.json` 中加入 `core:menu:default`（包含 new、append、popup 等）。

## 4. Windows / macOS 差异

- 原生菜单外观自动遵循平台：mac 是圆角毛玻璃，win 是 Win11 风格。`accelerator` 在 mac 上显示为 ⌘ 符号，在 win 上显示为 Ctrl。
- mac 上的 `popup` 会以鼠标位置为锚点；win 上需要传入 `LogicalPosition(event.clientX, event.clientY)`，统一传入即可。
- 子菜单中的歌单数量很多时，mac 菜单会自动滚动，win 会出现分页箭头，行为都可以接受。

## 6. 验收标准

- 在窗口右下角右键，菜单完整显示，没有被截断。
- 「添加到歌单」子菜单列出用户创建的歌单，点击后成功添加。
- 在收藏的歌单中右键歌曲，不出现「从歌单移除」。
- 生产包中在空白处右键，不出现「检查元素」或「重新加载」；在输入框中右键可以复制粘贴。
- 深色模式下两端的菜单样式都正常。

## 7. 风险与待决策项

- 原生菜单无法显示 iconify 图标。如果设计上要求菜单带图标，需要把图标导出为 PNG 通过 `Image` 传入，或者改用方案 B（待决策）。
- 每次右键都要新建 Menu 资源，需要在 popup 之后调用 `menu.close()` 释放 Rust 侧资源，避免泄漏。
