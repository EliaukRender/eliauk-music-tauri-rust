# 06 频谱图

## 1. 背景

### 旧实现位置

| 文件                                                                                                       | 内容                                                                                               |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `src/renderer/store/actions/audioPlayerActions.ts#createAnalyzer`                                          | 首次播放时创建 `AudioContext`，连接 `createMediaElementSource(audio)`、AnalyserNode 和 destination |
| `src/renderer/store/modules/analyzeReducer.ts`                                                             | `canvasOptions`：`fftSize=256`、`mode`、`colors[4]`、`stroke`、`bgColor`、`isGradient`             |
| `src/renderer/utils/analyze/{AnalyzeClass,renderAnalyze,drawBars,drawLightBars,drawerDoubleBars,tools}.js` | canvas 绘制，三种样式（经典 bars、荧光 lightBars、对称 doubleBars）加「关闭」，每 2 帧绘制一次     |
| `src/renderer/views/LyricFullScreen/components/AnalyzeCanvas.tsx`                                          | 全屏歌词页中的频谱画布                                                                             |
| `src/renderer/views/PlayerControlBar/components/{AnalyzeEntry,AnalyzeChart,AnalyzeColor}.tsx`              | 频谱调节弹窗：样式选择（带预览图）、8 套预设配色                                                   |
| `src/renderer/constant/index.ts`                                                                           | `AnalyzeChartList`、`AnalyzeColorList`                                                             |

### 已知缺陷

- `analyzeReducer` **没有持久化**，重启后自定义的样式和颜色会丢失。README 中宣称「自定义频谱图颜色、形状」，但实际上不会保存。
- `AnalyzeClass` 使用 `Object.assign(AnalyzeClass.getDefaultConfig, options)`。getter 每次都返回新对象，虽然不会污染默认值，但写法不直观。
- 每次 `isPlaying` 或 options 变化都会 new 一个实例并开启新的 rAF 循环，只有在 `mode === 'none'` 时才 cancel，**可能叠加多个 rAF 循环**。
- canvas 没有按 `devicePixelRatio` 缩放，在 Retina 屏上会模糊。
- 旧项目的音频来自自建后端（同源代理），因此没有暴露跨域问题。

## 2. 目标与范围

本期实现：

- 在全屏歌词页展示频谱（可选：控制栏迷你频谱）
- 迁移三种样式：经典、荧光、对称，外加关闭
- 8 套预设配色，另外支持自定义 4 色（使用 `NColorPicker`）
- 调节项：样式、配色、柱宽 `stroke`、灵敏度 `fftSize`（64 到 1024）
- 配置持久化
- 高 DPI 屏幕清晰；窗口不可见或暂停时停止绘制

本期不做：

- 3D 或 WebGL 可视化
- 均衡器

## 3. 方案设计

### 3.1 跨域问题：实测结论与方案

`MediaElementAudioSourceNode` 在媒体跨域且没有 CORS 授权时，会**输出静音**，AnalyserNode 拿到的数据全是 0。这是规范行为。

**实测（2026-09）**：`/song/url/v1` 返回的 `m7xx.music.126.net` 音频地址，无论 http 还是 https，都会返回 `Access-Control-Allow-Origin: *`，并支持 Range。所以：

| 方案                                  | 做法                                                                                                                                                                                                                                                                       | 优点                                                                                 | 缺点                                                                | 结论                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------- | ------------------------------ |
| A. 直连 CDN + CORS 模式               | `audio.crossOrigin = 'anonymous'`，URL 统一升级为 https（见 02）                                                                                                                                                                                                           | 零成本，流式播放，两种 API 形态都适用                                                | 依赖 CDN 持续返回 CORS 头；个别节点或不同源（如解灰音源）可能不返回 | **默认方案**                   |
| B. Rust 自定义 URI scheme 流式代理    | 用 `register_asynchronous_uri_scheme_protocol("ncmstream", ...)` 实现，前端写成 `ncmstream://localhost/?u=<encoded url>`（Windows 上是 `http://ncmstream.localhost/?u=...`）；Rust 端用 reqwest 转发 `Range` 请求头，流式返回数据，并附加 `Access-Control-Allow-Origin: *` | 与 CDN 的 CORS 策略解耦；两种 API 形态都适用；还可以统一处理 Referer、UA、https 升级 | 要实现 Range/206、大文件流式返回、取消请求；增加一层转发            | **兜底方案**，A 失败时自动切换 |
| C. 通过 sidecar 的 express 代理       | 在 sidecar 增加 `/proxy/audio` 路由                                                                                                                                                                                                                                        | 实现简单                                                                             | 只在内嵌形态可用，远程形态需要远程服务也部署代理                    | 不采用                         |
| D. fetch 整首歌后用 `decodeAudioData` | 完整下载后在 AudioBuffer 中播放                                                                                                                                                                                                                                            | 不受 CORS 限制（仍需 fetch 权限）                                                    | 不能边下边播，内存占用大，seek 复杂                                 | 不采用                         |

**自动降级逻辑**：audio-engine（02）在 `playing` 之后大约 1 秒，采样 5 帧 analyser 数据。如果全为 0，但 `audio.currentTime` 在推进且没有静音，就判定为 CORS 静音，改用方案 B 的 URL 重新加载，并从原位置 seek 继续。整个过程只标记一次（按域名缓存降级结果）。

方案 B 的 Rust 要点：

- 模块：`src-tauri/src/media_proxy.rs`，在 `lib.rs` 中通过 `.register_asynchronous_uri_scheme_protocol` 注册。
- 只允许代理 `*.music.126.net` 和 `*.126.net` 这两类 host 的白名单，防止被当作开放代理。
- reqwest 使用 `stream` feature，`bytes_stream()` 转成 body。Tauri 2 的 `UriSchemeResponder` 需要一次性给出 `Vec<u8>`，**不支持流式 body**。因此需要按 Range 分块：前端 audio 自己会发 Range 请求，代理对超过 2MB 的请求截断成 `bytes=start-(start+2MB)` 并返回 206，由媒体元素继续请求后续分块。
- 这个 feature 不依赖 `embedded-api`，两种形态都编译进去。

### 3.3 Store 设计：`stores/spectrum.ts`

```ts
const SpectrumMode = { None: 'none', Bars: 'bars', LightBars: 'light-bars', DoubleBars: 'double-bars' } as const
state: {
  mode: SpectrumMode       // 默认 'bars'
  colors: [string, string, string, string]
  presetId: string | null  // 选中预设时有值，自定义颜色时为 null
  stroke: number           // 1 到 6
  fftSize: 64 | 128 | 256 | 512 | 1024
  gradient: boolean
}
persist: true（全部字段）
```

`fftSize` 变化时调用 `engine.setFftSize`，不需要重建 AudioContext。

## 4. Windows / macOS 差异

| 项目                  | macOS                       | Windows                           | 处理                                                                     |
| --------------------- | --------------------------- | --------------------------------- | ------------------------------------------------------------------------ |
| 自定义协议的 URL 形式 | `ncmstream://localhost/...` | `http://ncmstream.localhost/...`  | 用 `convertFileSrc` 的同类逻辑封装 `toStreamUrl()`，按 `platform()` 拼接 |
| AudioContext 采样率   | 通常为 44.1k 或 48k         | 通常为 48k                        | 与 AnalyserNode 无关，不需要处理                                         |
| 高 DPI                | Retina dpr=2                | 缩放 125%/150% 时 dpr 为 1.25/1.5 | canvas 使用 `width = cssWidth * dpr`                                     |
| 后台节流              | 最小化后 rAF 停止           | 同左                              | 本身就会停，额外监听 visibility 显式停止                                 |

CSP 需要允许 `media-src ncmstream: http://ncmstream.localhost`，并在 capabilities 中确认自定义协议不需要额外权限（协议注册在 Rust 端完成）。

## 6. 验收标准

- 两个平台播放任意在线歌曲时频谱都有跳动。
- 切换样式、配色、fftSize 后立即生效，重启后仍然保留。
- 连续切换样式 20 次后，Performance 面板中只有一个 rAF 回调。
- 暂停或页面隐藏时 CPU 占用回落。
- 人为把 audio 的 `crossOrigin` 去掉来模拟 CORS 失败，能自动降级到方案 B，并且播放不中断（只允许一次小于 500ms 的卡顿）。
