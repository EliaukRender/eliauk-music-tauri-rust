## 里程碑规划

骨架阶段已经完成：工程初始化、API 双形态（内嵌 sidecar / 远程）、主窗口（mac Overlay 标题栏 / win 自绘按钮）、基础托盘、single-instance、window-state、log。以下里程碑都在骨架之上推进。

### M1 播放闭环（优先级 P0）

目标：不登录也能搜索或打开推荐歌单，双击歌曲播放，并能完成完整的控制栏操作。

- 02 播放内核：`services/player/audio-engine.ts`、`stores/player.ts`、`components/layout/PlayerBar.vue`
- 03 播放队列
- 公共歌曲列表组件 `components/song/SongList.vue`（双击播放、当前歌曲高亮），供歌单、音乐馆、搜索复用

### M2 歌单与登录（P0）

- 01 二维码登录：`stores/user.ts` 保存 cookie，由 `api/http.ts` 统一注入
- 04 用户歌单：侧边栏「我的歌单」数据源切到 `/user/playlist`
- 11 喜欢歌曲：控制栏红心，歌曲列表喜欢状态
- 09 右键菜单：歌曲项的「播放 / 下一首播放 / 添加到歌单 / 从歌单删除」

### M3 歌词与频谱（P1）

- 05 全屏歌词页：LRC 与逐字 YRC 解析、滚动定位、唱片机
- 06 频谱图：AnalyserNode，形状和颜色可自定义并持久化

### M4 多窗口与系统集成（P1）

- 07 mini 播放器窗口
- 08 窗口控制剩余项、托盘播放菜单、应用内快捷键、全局快捷键、媒体键

### M5 音乐馆等内容页（P2）

- 10 音乐馆：精选（轮播 + 推荐歌单）、排行榜、歌手
- 旧项目的「视频」「世界」只是占位页，本次不迁移，是否保留入口待定

## 跨功能约定

- **API 调用**：一律经 `src/api/http.ts`，它负责解析 baseURL（内嵌模式经 `services/tauri/api-endpoint.ts` 调用 `invoke('get_api_endpoint')`，远程模式读 `VITE_API_BASE_URL`），并在请求中注入 `cookie`（骨架已实现；防缓存的 `timestamp` 在 M2 登录时补齐，见 01）。业务代码不要直接用 axios。
- **歌曲数据模型**：统一为 `src/types/music.ts` 中的 `Song` 类型，由 `src/api/adapters/song.ts` 把 `/song/detail`、`/playlist/track/all`、`/search` 等接口的不同字段（`ar`/`artists`、`al`/`album`、`dt`/`duration`）归一化。这样可以避免旧项目那样到处都是 `any`。
- **跨窗口通信**：统一使用 Tauri 事件（`emit` / `listen`），事件名集中定义在 `src/constants/events.ts` 的 const 对象中。Rust 端事件名集中定义在 `src-tauri/src/events.rs`。
- **持久化**：用户偏好（音量、播放模式、音质、频谱配置、主题）使用 pinia-plugin-persistedstate 存入 localStorage。播放队列体积较大，只持久化 id 列表，冷启动时再用 `/song/detail` 补全。
