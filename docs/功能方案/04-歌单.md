# 04 用户歌单

## 1. 背景

### 旧实现位置

| 文件                                                                        | 内容                                                                                                                             |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `src/renderer/api/modules/musicService.ts`                                  | 自建后端接口：`querySheetList`、`querySongListBySheetId`、`createSheet`、`deleteSheet`、`moveSongToSheet`、`deleteSongFromSheet` |
| `src/renderer/store/actions/mainMenuActions.ts`                             | `initAppData`、`initSheetMenu`、`handleCreateSheet`、`handleDeleteSheet`、`handleDeleteSongFromSheet`、`handleMoveSongToSheet`   |
| `src/renderer/store/modules/mainMenuReducer.ts`                             | `sheetMenuList`、`activeSheet`、`curSheetSongList`、`sheetSongListMap`                                                           |
| `src/renderer/views/Layout/components/LeftSheetMenu.tsx`、`CreateSheet.tsx` | 侧边栏歌单菜单；新建时出现内联输入框，失焦后提交，默认名称为「新建歌单 N」                                                       |
| `src/renderer/views/components/MenuItem/SheetMenu.tsx`                      | 歌单右键菜单：播放（随机一首）、删除歌单（默认歌单禁用）、重命名（未实现）                                                       |
| `src/renderer/views/SheetCommon/*`                                          | 歌单页：`SheetIntroduce` 头部与 `SheetSongList` 列表                                                                             |

### 现有行为

- 启动时拉取全部歌单，并**并发拉取每个歌单的全部歌曲**，放进 `sheetSongListMap`。
- 默认激活第一个歌单。

### 已知缺陷

- 启动时 N 个歌单就发 N+1 个请求，歌单多的时候启动很慢。
- 删除歌单后直接取 `sheet[0]`，如果删光了会报错。
- 重命名没有实现。
- 添加歌曲后只重新请求了列表，没有写回 store。
- 数据模型是自建后端的（`sheetId`、`songId`、`songUrl`），与网易云不兼容。

## 2. 目标与范围

数据源从自建后端切换到**网易云用户歌单**，需要登录（依赖 01）。

本期实现：

- 侧边栏分组展示「创建的歌单」「收藏的歌单」，其中「我喜欢的音乐」置顶
- 歌单详情页：头部（封面、名称、创建者、描述、歌曲数、播放全部）+ 全部歌曲列表（虚拟列表）
- 新建歌单（名称、是否隐私）
- 删除歌单（只能删除自己创建的，「我喜欢的音乐」不可删）
- 重命名（补齐旧项目缺失的能力）
- 向歌单添加歌曲、从歌单移除歌曲
- 未登录时，侧边栏显示登录引导

本期不做：

- 歌单封面上传、标签编辑、歌单排序、收藏或取消收藏他人歌单（后续加入 10 音乐馆时一起做）

### 3.2 Store 设计：`stores/playlist.ts`

```ts
type Playlist = {
  id: number; name: string; coverUrl: string; trackCount: number
  creatorId: number; privacy: 0 | 10; specialType: number /* 5 = 我喜欢的音乐 */
  subscribed: boolean
}
state: {
  mine: Playlist[]                               // /user/playlist 的结果，不持久化，启动后拉取
  detailCache: Map<number, { meta: Playlist; songs: Song[]; loadedAt: number }>  // LRU，最多 20 个
}
getters: created（creatorId === userId）、subscribed、likedPlaylist（specialType === 5）
actions: {
  fetchMine()                   // 登录后或登录态变化时调用
  fetchDetail(id, force?)       // 先取 /playlist/detail 的元数据，再取 /playlist/track/all 分页数据
  create(name, privacy)         // 成功后 unshift 到 mine
  remove(id)                    // 删除后如果当前路由在该歌单，跳转到发现页（修复空数组时的报错）
  rename(id, name)
  addSongs(pid, songIds)        // 成功后 trackCount + n，并让 detailCache 失效
  removeSongs(pid, songIds)     // 乐观更新，失败时回滚
}
```

**与旧实现的关键区别**：不再在启动时拉取所有歌单的歌曲，而是**进入详情页时按需拉取**，并做 LRU 缓存。旧的 `curSheetSongList` 概念被路由参数和 `detailCache` 取代；「播放队列」完全由 player store 负责（修复 02 中的缺陷 2）。

### 3.3 接口

| 接口                         | 关键参数                                   | 说明                                                         |
| ---------------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| `GET /user/playlist`         | `uid`、`limit=1000`                        | 用户的创建歌单和收藏歌单                                     |
| `GET /playlist/detail`       | `id`                                       | 元数据；`trackIds` 包含全部 id                               |
| `GET /playlist/track/all`    | `id`、`limit`、`offset`                    | 分页获取歌曲（每页 500），解决 detail 只返回前 1000 首的问题 |
| `POST /playlist/create`      | `name`、`privacy`（`10` 表示隐私）         |                                                              |
| `GET /playlist/delete`       | `id`                                       |                                                              |
| `POST /playlist/name/update` | `id`、`name`                               |                                                              |
| `POST /playlist/tracks`      | `op=add\|del`、`pid`、`tracks`（逗号分隔） | 添加或移除歌曲                                               |

注意：`/playlist/tracks` 偶尔会返回 `code=502`，表示歌曲已存在。前端要把它识别成「已在歌单中」，而不是报错。

### 3.4 数据流

```
登录成功（01） → watch isLoggedIn → playlistStore.fetchMine() → SideMenu 渲染
点击侧边栏歌单 → router.push(`/playlist/${id}`) → PlaylistView onMounted/watch(id) → fetchDetail(id)
「播放全部」 → player.playSongs(detail.songs)
歌曲右键「添加到歌单」 → AddToPlaylistModal → playlistStore.addSongs
```

无。

## 4. Windows / macOS 差异

- 删除歌单的二次确认统一使用 naive-ui 的 `useDialog`，不调用系统原生对话框，保证两端交互一致。
- 侧边栏在 mac 下顶部要给红绿灯留出空间（约 72px 宽、28px 高的安全区）。这是骨架的 `TitleBar` 已经处理的内容，此处只需要复用 CSS 变量 `--titlebar-height`。

## 6. 验收标准

- 登录后 1 秒内显示侧边栏歌单；启动时只发 1 个歌单列表请求。
- 3000 首歌的歌单详情页滚动流畅，能看到全部歌曲（不止前 1000 首）。
- 新建、重命名、删除歌单后，侧边栏立即更新；删除当前正在查看的歌单后跳转到发现页。
- 在网络断开的情况下移除歌曲，UI 会回滚并提示失败。
- 「我喜欢的音乐」不出现删除入口。

## 7. 风险与待决策项

- 旧项目自建后端里的歌单数据**不迁移**（已决策）。
- 网易云对短时间内频繁修改歌单有频率限制，批量添加时需要合并成一次请求。
- 删除歌单是不可恢复的操作，必须二次确认。
